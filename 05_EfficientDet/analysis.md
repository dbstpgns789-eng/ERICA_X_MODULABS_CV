## 채점 오류 여부 확인

처음에는 Roboflow의 category_id가 0부터 시작하는 것과 저장소의 `label + 1`
채점이 어긋나는 것을 의심했다. 저장소 코드를 확인한 결과 데이터 로더가
`category_id - 1`로 읽고 채점기가 `label + 1`로 되돌리므로 서로 맞는다. 채점
오류가 아니라 실제 성능이다.

부수적으로, 로더가 `-1`을 하므로 `obj_list`에서 더미 `cars`를 빼야 시각화
클래스 이름이 맞는다. 점수에는 영향이 없다.

## 로컬 추론으로 확인한 것

학습된 가중치(`efficientdet-d0_28_232.pth`)로 test 6장을 CPU에서 추론했다.
`results/test1/` 참고.

| 이미지 | 정답 박스 | 예측 (≥0.05) | 예측 (≥0.3) | 최고 점수 |
| --- | --- | --- | --- | --- |
| frame_0990 | 36 | 13,177 | 15 | 0.43 |
| frame_1004 | 22 | 13,521 | 33 | 0.51 |

1. **신뢰도 0.05 이상 박스가 한 장에 13,000개.** 배경에도 0.1~0.3 점수를 준다.
   `pred_all_boxes.png`에서 주황색이 화면을 덮은 것이 이것이다.
2. **최고 신뢰도가 0.5를 넘지 못한다.** 맞는 박스도 확신이 없다.
3. **0.3 이상만 남기면** 가까운 차들은 정답 위에 박스가 겹친다
   (`pred_conf_over_0.3.png`). 모델이 아예 못 배운 것은 아니다.
4. **화면 절반을 덮는 거대 박스**가 여러 개 있다. 벽과 도로를 물체로 잡은 오탐.
5. **멀리 있는 작은 차들**에는 박스가 없다. AP small 0.004와 일치한다.
6. **학습 사진과 구도가 다른 두 장**(frame_3837, frame_4363)은 0.3 이상 박스가 없다.

## 원인

### 주원인: 학습량 부족

| | YOLOv8 (stamp) | EfficientDet (차량) |
| --- | --- | --- |
| 학습 이미지 | 1,100 | 136 |
| epoch당 걸음 수 | 69 | 8 |
| 총 걸음 수 | 1,380 | **320** |

분류 헤드가 COCO 90클래스에서 6클래스로 새로 초기화되어 첫 손실이 14,036이었다.
320걸음으로는 "이 자리에 물체 없음"을 충분히 배우지 못해, 배경 점수가 0 근처까지
내려가지 않은 상태로 끝났다. 수천 개의 낮은 점수 박스가 COCO 평가의 maxDets=100
안에 섞여 들어가 정밀도와 재현율을 모두 무너뜨린다.

### 부원인 1: 앵커 설정

`anchors_scales`의 2.13은 P7(stride 128)에서 4×128×2.13 = 1,090px 앵커를 만든다.
640px 이미지보다 크다. 이런 앵커에는 정답이 하나도 매칭되지 않아 회귀 헤드가
학습되지 않고, 임의의 거대 박스를 내놓는다.

### 부원인 2: 작은 객체

정답 박스 중앙값이 약 18px이고 입력을 512로 줄이면 14px이 된다. 가장 작은
앵커(P3, 9×17px)와 겨우 맞는 수준이라 매칭되는 양성 앵커가 적다.

### 부원인 3: 구도 다양성

136장 대부분이 같은 고가도로 CCTV 구도다. 다른 구도(블랙박스 시점 등)는 학습에
거의 없어 일반화되지 않는다.

## 테스트 1 재실행 (2026-09-16)

같은 설정으로 다시 돌렸더니 valid mAP50이 0.059 → 0.010으로 내려갔다. 설정이 같은데
결과가 이렇게 흔들리는 것은 학습이 짧아서 초기값과 순서에 좌우된다는 뜻이다. 이 실행에서는
2단계 셀이 같은 폴더의 이전 체크포인트(`_29_240`)를 불러와 학습을 건너뛰는 버그도
드러났다. 실행마다 별도 폴더를 써야 한다.

## 테스트 2: epoch를 늘려 다시 학습

헤드 20 + 전체 80 epoch (총 100). 나머지 설정 동일. `run2/`에 별도 저장. 최종 가중치
`efficientdet-d0_87_704.pth`, 즉 epoch 87까지 val 손실이 계속 개선됐다.

| | 테스트 1 (40 epoch) | 테스트 2 (100 epoch) | 배수 |
| --- | --- | --- | --- |
| valid mAP50 | 0.010 | **0.265** | 26배 |
| valid mAP50-95 | 0.006 | **0.158** | 26배 |
| valid small / medium / large | 0.000 / 0.041 / 0.004 | 0.054 / 0.340 / 0.496 | |
| test mAP50 | 0.012 | **0.144** | 12배 |
| test mAP50-95 | 0.008 | 0.093 | |
| test small / medium / large | 0.000 / 0.048 / 0.000 | 0.056 / 0.369 / 0.350 | |

`results/test2/pred_conf_over_0.2.png`에서 확인한 것:

1. 가까운 차들은 노란 예측 박스가 초록 정답 위에 정확히 겹친다. 테스트 1에서 0개였던
   노란 박스가 14~54개로 늘었다.
2. 구도가 다른 frame_3837도 13개를 잡는다. 테스트 1에서는 0개였다.
3. **남은 문제 세 가지.** 멀리 있는 작은 차들에는 여전히 박스가 없다(small AP 0.054).
   한 차에 박스가 2~3개 겹친다. 블랙박스 구도(frame_4363)는 여전히 0개다.
4. 거대 박스는 frame_1806에 하나 남았다. 앵커 문제는 epoch로 해결되지 않는다.

**학습량 부족이라는 주원인 가설은 확인됐다.** 부원인(앵커, 작은 객체, 구도 다양성)은
그대로 남았고, 각각 별도 실험이 필요하다.

## 테스트 2 계획 (실행 전 메모)

**epoch를 늘려 다시 학습한다.** 헤드 30 → 전체 120. "학습량이 부족했다"는
주원인 가설을 직접 확인하는 실험이다. 다른 설정은 그대로 두어 변화의 원인을
하나로 고정한다.

예상: 배경 점수가 내려가면서 0.05 이상 박스 수가 크게 줄고, 최고 신뢰도가
올라가며, mAP50이 눈에 띄게 오른다. 다만 거대 박스(앵커)와 작은 객체 문제는
남을 것이다.

## 회고 재료
