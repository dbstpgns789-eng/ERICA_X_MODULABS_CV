# EfficientDet 기반 제조 영상 분석 최적화

차량 탐지 데이터셋(Vehicles_Detection)으로 EfficientDet-D0를 학습하고, 검증·테스트 세트에서
평가한 뒤 epoch를 늘려 다시 학습해 비교한 프로젝트입니다.

> 모두의연구소 AX Bootcamp · 제조업 이상탐지 트랙 · 프로젝트 노드 2

## 데이터

| 항목 | 내용 |
| --- | --- |
| 출처 | Roboflow Universe `Vehicles_Detection` v9i (흑백 적용본) |
| 장면 | 고가도로 CCTV에서 내려다본 도로, 일부 블랙박스 시점, 640×640 |
| 클래스 | Bus, Car, Motorcycle, Pickup, Truck (+ Roboflow 더미 `cars`) |
| 분할 | train 136 / valid 28 / test 13 |
| 클래스 불균형 | Car 2,023개 vs Bus 31개 (65배) |

## 학습 설정

| 항목 | 값 |
| --- | --- |
| 모델 | EfficientDet-D0, COCO 사전학습 (`zylo117/Yet-Another-EfficientDet-Pytorch`) |
| 학습 방식 | 1단계 헤드만 → 2단계 전체 |
| 앵커 | scales `[0.54, 1.0, 2.13]`, ratios `[(0.52,1), (0.67,1), (0.82,1)]` (데이터 분석 기반) |
| mean/std | 학습 이미지 136장으로 직접 계산 |
| GPU | Colab T4 |

## 결과

### 테스트 1: 기본 설정 (헤드 10 + 전체 30 epoch, 총 320걸음)

| | valid | test |
| --- | --- | --- |
| mAP50 | 0.010 | 0.012 |
| mAP50-95 | 0.006 | 0.008 |
| small / medium / large | 0.000 / 0.041 / 0.004 | 0.000 / 0.048 / 0.000 |

학습 손실은 정상적으로 내려갔지만(val 17,997 → 3.1) mAP는 0에 가까웠다. 신뢰도 0.4
이상 예측이 6장 중 한 개도 없었고, 0.05 이상 박스는 한 장에 13,000개였다.

### 테스트 2: epoch만 늘림 (헤드 20 + 전체 80 epoch)

| | valid | test |
| --- | --- | --- |
| mAP50 | **0.265** (26배) | **0.144** (12배) |
| mAP50-95 | 0.158 | 0.093 |
| small / medium / large | 0.054 / 0.340 / 0.496 | 0.056 / 0.369 / 0.350 |

## 주요 발견

1. **학습량 부족이 주원인.** 136장 × 40 epoch = 320걸음으로는 새로 만든 분류 헤드가
   "배경은 0점"을 배우지 못했다. epoch만 100으로 늘려 26배가 올랐다.
2. **손실은 좋은데 mAP가 0일 수 있다.** 손실 곡선만 보고 판단하면 안 된다.
3. **그림도 속인다.** 신뢰도 0.4 이상만 그리면 예측이 하나도 안 보여서 정답 박스(초록)만
   남는데, 이걸 예측으로 착각했다. 채점은 0.05 이상 상위 100개를 보므로 그 아래의 오탐이
   점수를 무너뜨린다.
4. **같은 설정을 두 번 돌려도 결과가 다르다.** 0.059와 0.010. 학습이 짧을수록 흔들린다.
5. **epoch로 해결되지 않는 것.** 멀리 있는 작은 차(small AP 0.05), 한 차에 겹친 박스
   2~3개, 화면보다 큰 앵커가 만드는 거대 박스, 그리고 학습에 거의 없던 블랙박스 구도.

자세한 근거와 로컬 대조 분석은 [`analysis.md`](analysis.md)에 있습니다.

## 강사 노트북 대비 수정한 것

원본 노트북을 그대로 따라가면 멈추는 지점을 고쳤습니다.

| 문제 | 조치 |
| --- | --- |
| 설정 파일(yml)을 만드는 셀이 없음 | mean/std·obj_list를 계산해 자동 생성 |
| `num_gpus: 0` → CPU로 학습됨 | `1`로 |
| `verbose=True` → 최신 torch에서 오류 | `sed` 패치 |
| 체크포인트 파일명 하드코딩 | 최신 파일 자동 탐색 (단, 실행마다 별도 폴더 필요) |
| 추론 시 학습과 다른 앵커 사용 | yml에서 읽어 동일하게 |
| mean/std를 컬러본으로 계산하고 흑백본으로 학습 | 학습 데이터로 직접 계산 |

## 회고

**Keep**

- mean/std를 학습에 쓰는 바로 그 데이터로 직접 계산한 것.
- 헤드만 먼저 학습하고 그다음 전체를 학습하는 두 단계 방식.
- 결과가 안 나왔을 때 설정을 이것저것 만지지 않고 epoch부터 늘려본 것. 그 하나로 26배가 올랐다.

**Problem**

- 손실은 정상적으로 내려갔는데 mAP가 0.01이었다. 손실만 보고 잘 됐다고 판단할 뻔했다.
- 그림에서 초록 정답 박스를 모델 예측으로 착각했다. 한글 제목이 깨져서 범례를 못 읽었다.
- 흑백본으로 학습했는데 컬러본이었으면 달랐을지 확인하지 못했다.

**Try**

- epoch를 300까지 늘려본다. 테스트 2에서 87 epoch까지 val 손실이 계속 개선됐다.
- 앵커를 COCO 기본값으로 되돌려 비교한다. 거대 박스가 사라지는지 본다.
- 클래스별 AP를 출력하도록 평가 코드를 고쳐서 Bus(31개)가 실제로 얼마나 안 되는지 확인한다.
