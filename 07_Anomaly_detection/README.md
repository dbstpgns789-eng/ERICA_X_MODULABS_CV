# 제조업 실시간 이상탐지: PaDiM · AutoEncoder · One-Class SVM

VisA 데이터셋의 PCB(`pcb4`)로 정상 사진만 학습하는 이상탐지 모델 세 가지를 비교하고,
강사 노트북의 결과가 왜 그렇게 나왔는지를 실험 11개로 추적한 프로젝트입니다.

> 모두의연구소 AX Bootcamp · 컴퓨터 비전 · 프로젝트 노드 6

## 데이터

| 항목 | 내용 |
| --- | --- |
| 출처 | VisA (Amazon, `VisA_20220922.tar`) 중 `pcb4` |
| 구성 | 정상 1,005장 · 불량 100장 (결함 유형 27종: missing, extra, dirt, damage 등) |
| 학습 | **정상만** 804장 (정상의 앞 80%) |
| 시험 | 정상 201장 + 불량 100장 전부 |
| 백본 | Wide-ResNet50 (ImageNet 사전학습, 가중치 고정) |
| GPU | Colab T4 |

불량은 드물고 종류를 미리 다 알 수 없으므로, 정상이 어떻게 생겼는지만 배우고
거기서 벗어난 정도를 점수로 씁니다.

![불량 예시](results/sample_with_mask.png)

시험 세트의 불량 사진 예시입니다. 마스크의 흰 부분이 결함(damage, dirt) 위치입니다.

## 실행 흐름

```mermaid
flowchart LR
    A[VisA 다운로드] --> B[Dataset<br/>정상 80% 학습<br/>정상 20%+불량 시험]
    B --> C[Wide-ResNet50<br/>layer 특징 추출]
    C --> D1[PaDiM<br/>칸별 평균·공분산<br/>마할라노비스 max]
    C --> D3[One-Class SVM<br/>전체 평균 특징<br/>rbf 울타리]
    B --> D2[AutoEncoder<br/>압축→복원<br/>픽셀 오차 평균]
    D1 --> E[평가<br/>AUROC·AUPRC·F1]
    D2 --> E
    D3 --> E
    D1 --> F[pickle 저장<br/>평균·공분산·투영행렬]
    F --> G[Gradio<br/>점수·히트맵·판정]
```

## 결과

### 강사 노트북 그대로

| 모델 | AUROC | AUPRC | Best F1 |
| --- | --- | --- | --- |
| PaDiM | 0.958 | 0.890 | 0.865 |
| One-Class SVM | 0.827 | 0.717 | 0.669 |
| AutoEncoder | **0.265** | 0.226 | 0.525 |

![강사 노트북 ROC](results/baseline_roc.png)

AutoEncoder의 ROC 곡선이 대각선(동전 던지기)보다 아래에 있습니다. 점수 분포를 보면 불량(주황)이 정상(파랑)보다
대체로 더 낮은 점수를 받고 있어서, 모델이 거꾸로 채점하고 있다는 것이 보입니다.

![강사 노트북 점수 분포](results/baseline_score_distribution.png)

### 원인을 고친 뒤

| 모델 | 바꾼 것 | AUROC |
| --- | --- | --- |
| PaDiM | 학습 뒤집기 제거 + layer1 추가 | 0.958 → **0.979** |
| One-Class SVM | 학습 뒤집기 제거 | 0.817 → **0.872** |
| AutoEncoder | 디코더 끝 Sigmoid 제거 | 0.271 → **0.928** |

화살표 왼쪽은 고치기 전 설정을 같은 조건으로 다시 돌린 값입니다(SVM은 실험 9의 시드 3개 평균, AE는 실험 7의 20 epoch).
위의 강사 노트북 표(0.827, 0.265)와 조금 다른 이유입니다.

![고친 전후](results/fix_before_after.png)

## 주요 발견

1. **AutoEncoder 0.265는 출력 범위 고장이었다.** 입력은 Normalize로 −2.1\~+2.6인데 출력은
   Sigmoid 때문에 0\~1에 갇힌다. 모델 없이 "0\~1 밖으로 나간 픽셀 양"만으로 점수를 매겨도
   0.25가 나와서(원래 모델 0.27), 원래 모델도 결함이 아니라 극단 색 픽셀 양을 재고 있었던 것으로 보인다.
   loss도 5 epoch 이후 1.6대에서 멈춰서, epoch를 늘려도 나아질 수 없는 구조였다.

   ![AE loss](results/ae_loss.png)

2. **이상탐지에서 증강은 "정상"의 범위를 넓힌다.** 학습 때 좌우 뒤집기를 켜면 PaDiM은
   위치별 정상 분포가 섞이고(0.974 → 0.958), SVM은 정상 무리가 두 덩어리가 되어
   울타리가 넓어진다(0.872 → 0.817). 시험에 나오지 않을 변형까지 정상으로 넓히면 불량이
   그 안에 숨는다.

   ![뒤집기](results/flip_on_off.png)

3. **PaDiM이 잘 되는 이유를 하나씩 바꿔 보며 확인했다.** 얕은 층의 세밀한 위치(layer4만 쓰면 0.928),
   마할라노비스(유클리드로 바꾸면 0.909), max 채점(mean으로 바꾸면 0.931). 위치별로 정상을 저장하는
   방식 자체를 빼 보지는 못했고, 뒤집기 실험(2번)으로 간접적으로만 봤다.
4. **Gradio의 판정 기준 15는 정상 사진의 67%를 불량으로 판정한다.** 이 모델의 정상 점수
   중앙값이 17.6이다. 강의에서 말한 23.3은 다른 모델의 값이고, 셀 [23]의 최적 임계값은
   시험 세트로 골라서 낙관적이다.

   ![임계값](results/threshold_range.png)

5. **고친 AutoEncoder는 20 epoch면 충분했다.** 50 epoch 동안 epoch마다 검증 loss(학습에 안 쓴 정상 80장)와 시험 AUROC를
   기록했다. 검증 loss는 47 epoch까지 조금씩 내려갔지만, AUROC는 20 epoch쯤 0.92에 닿은 뒤 ±0.01 안에서 흔들리기만 했다.
   시험 AUROC 최고(39 epoch, 0.935)를 고르면 그 흔들림 중 운 좋은 값을 고르는 셈이라, epoch는 검증 loss로 골랐다(47 epoch, 0.925).

   ![epoch](results/ae_epochs.png)

6. **비교할 때는 시험지를 고정해야 한다.** `train_ratio`를 바꾸면 학습 장수와 시험지가
   같이 바뀌어 비교가 무의미해진다. 무작위만으로 ±0.002 흔들리므로 시드를 고정해 3번씩 돌렸다.

   ![학습 장수](results/train_size.png)

실험별 조건 · 내 예측 · 결과 · 해석은 [`analysis.md`](analysis.md)에 있습니다.

## 강사 노트북에서 발견한 것

셀 번호는 강사 원본 노트북 기준이다. 제출 노트북은 내가 마크다운 셀을 끼워 넣어서 몇 칸씩 밀려 있다.

| 위치 | 내용 | 영향 |
| --- | --- | --- |
| 셀 [21] | 디코더 끝 `nn.Sigmoid()` vs Normalize 입력 | AE AUROC 0.27 |
| 셀 [9] | 학습에 `RandomHorizontalFlip` | PaDiM −0.016, SVM −0.055 |
| 셀 [39] | 판정 기준 `score > 15` 하드코딩 | 정상 67% 오탐 |
| 셀 [24] vs [38] | PaDiM 층이 서로 다름 (layer2+3 / 1+2+3) | 저장한 모델과 임계값을 옮겨 쓸 수 없음 |

이 밖에 셀 [18]의 `warnings.filterwarnings('ignore')` 때문에 시험 세트가 망가져도 `nan`만 조용히 나왔고(실험 1),
셀 [23]은 시험 세트로 임계값을 고른 뒤 같은 세트로 F1을 내서 성적이 낙관적이다. 셀 [39]의 히트맵은 사진마다
min-max로 늘려 칠해서 정상 사진에도 빨간 곳이 생긴다. 코드를 옮기다 보니 PaDiM 무작위 투영에 시드가 없는 것도 보였는데,
실험 3에서 같은 804장인데 0.002 차이가 난 이유로 보인다.

## 구조

```
.
├── README.md                              이 문서
├── analysis.md                            실험 11개의 조건 · 결과 · 해석
├── anomaly_detection_visa_pcb4.ipynb      강사 노트북 + 실험 셀 11개
├── src/
│   ├── dataset.py     VisA 데이터셋 · 로더 (학습 뒤집기는 flip=False 기본)
│   ├── models.py      FeatureExtractor, PaDiM, AutoEncoder, One-Class SVM
│   ├── evaluate.py    AUROC · AUPRC · F1, 정상 점수 분포로 임계값 정하기
│   ├── run.py         세 모델 학습 · 평가, PaDiM 저장
│   └── figures.py     README 그림 (노트북 출력 + 실험 숫자 그래프)
└── results/           그림
```

노트북 코드를 모듈로 옮기면서 실험에서 확인한 것을 기본값으로 바꿨습니다.

| 노트북 | `src/` 기본값 | 근거 |
| --- | --- | --- |
| 학습 때 좌우 뒤집기 | 끔 (`flip=False`) | 실험 4 · 9 |
| AutoEncoder 디코더 끝 Sigmoid | 제거 (`sigmoid=False`) | 실험 7 |
| `warnings.filterwarnings('ignore')` | 넣지 않음 | 실험 1 |
| 시험 세트로 임계값 선택 | `threshold_from_normal()` 추가 | 실험 10 |
| PaDiM 층: 셀 [24] layer2+3, Gradio layer1+2+3 | layer1+2+3로 통일 | 실험 5 |
| 시드 없음 | `seed=0` | 실험 3 (±0.002) |

PaDiM 채점(max/mean)과 거리(마할라노비스/유클리드)는 실험 6처럼 인자로 바꿀 수 있습니다.

```bash
python src/run.py ./VisA pcb4     # 세 모델 학습 · 평가 (GPU 권장)
python src/figures.py             # results/ 그림 다시 만들기
```

`src/` 주석의 셀 번호는 제출 노트북 기준이다.
`run.py`는 VisA 데이터가 없는 로컬에서 작은 가짜 데이터셋으로 끝까지 도는 것만 확인했습니다. 실제 점수는 노트북 결과를 기준으로 합니다.

## 회고

**Keep**

- 셀마다 결과를 먼저 예측하고 돌려 본 것. 예측이 틀린 곳(AE max, SVM 뒤집기)에서 가장 많이 배웠다.
- 시험지를 고정하고 한 가지만 바꾸는 실험 설계. 시드 3개로 반복해서 우연과 효과를 구분한 것.
- 강의에서 "조금 아쉽다"고 넘어간 AE 0.265를 그냥 받아들이지 않고 원인을 끝까지 추적한 것.

**Problem**

- 강의를 들었는데도 처음엔 노트북 전체가 뭘 하는지 몰랐다. 주석을 읽기만 하고 돌려 보지 않았다.
- `train_ratio`를 "정상 80 · 불량 20 학습"으로 잘못 알고 있었다.
- 실험 2에서 시험지까지 같이 바뀐 걸 처음엔 못 봤다.
- "위치를 안 보는 SVM은 뒤집어도 같다"고 예측했는데 틀렸다. CNN 특징이 좌우 대칭이 아니라는 걸 몰랐다.

**Try / Action**

- [ ] 검증용 정상 사진을 따로 떼고 그 점수의 99퍼센타일로 임계값을 정해, 시험 세트의 실제 오탐률과 비교한다.
- [ ] Gradio 히트맵을 고정 눈금(0 \~ 임계값)으로 바꾸고 정상·불량 사진 각 3장으로 화면을 확인한다.
- [ ] 결함 유형별(missing / scratch / dirt)로 AUROC를 나눠서 layer4가 어떤 결함에서 무너지는지 본다.
- [ ] 대칭인 카테고리(capsules, candle)에서 뒤집기 실험을 반복해 "대칭이면 괜찮다"는 예측을 확인한다.
